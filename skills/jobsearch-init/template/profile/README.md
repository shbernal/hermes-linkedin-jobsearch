# Profile

Every fact about the user that could reach a resume or a form answer. If a fact isn't here, it isn't used.

- `about.md`: name, contact, location, languages, work authorization, and anything that isn't tied to one school, job or project.
- `skills.md`: each skill linked to the file that shows it in use.
- `experience/<employer>.md`, `education/<school>.md`, `projects/<project>.md`: one file each.
- `sources/<project>-<what>.pdf`: a document that backs a fact when its only other copy could disappear. Compress PDFs first. Cite large files by path instead.

Each experience, education and project file has these sections, in order:

1. A facts list: dates, location, role.
2. Context about the organization, for a reader who has never heard of it.
3. What the user did: plain statements with the tools, the audience and the result, in more detail than a resume has room for.
4. Earlier resume wording, quoted with where it came from, unconfirmed until the user confirms it.
5. Open questions.

- Write what happened, not a polished bullet. Polishing happens when a resume is tailored.
- Every number has a source and says whether it's a count, an estimate or a published figure.
- A fact the user states in a session is recorded with its date.
- When two versions disagree, both stay under open questions until the user settles it. An answered question moves into the body.
- A confidential client is described by sector until the user allows its name.
